# 온보드 카메라 (T-cam) — 시스템 구성

Baja 차량에 F1 T-cam 처럼 고화질 카메라를 달고, 팀 웹 (SEM Workbench) 에서 로그인한 팀원이 라이브로 보는 구성입니다.

```
[차량]    카메라 모듈 3 Wide ─CSI─ 라즈베리 파이 4 (MediaMTX) ─USB─ LTE 모뎀 + 외부 안테나
            · H.264 하드웨어 인코딩 · 차 안 녹화 (fMP4, 1 초 조각)
            · 전원: 12 V 배터리 ─ 퓨즈 ─ DC-DC 5 V 5 A
              │
              │  SRT over LTE (AES 암호 + 송출 토큰)
              ▼
[중계]    클라우드 VM (서울): MediaMTX + Caddy (HTTPS) · 백업 녹화
              │                         ▲
              │  WebRTC (WHEP, HTTPS)   │ Worker 공개 키 (JWKS) 로 토큰 검사
              ▼                         │
[팀 웹]   SEM Workbench 라이브 탭 ──── 시청 토큰 요청 ────▶ sem-ai Worker (세션 확인 → 30 분 JWT)
```

| 항목 | 목표 |
|---|---|
| 화질 | 1920×1080 30 fps, 4 Mbps (LTE 가 약하면 1280×720 2 Mbps) |
| 지연 | 약 1 ~ 1.5 초 예상 (인코딩 + SRT 재전송 여유 0.8 초 + WebRTC). 실제 LTE 에서 재 볼 것 |
| 상향 데이터 | 4 Mbps ≈ 시간당 1.8 GB (2 시간 내구 ≈ 3.6 GB) |
| 끊김 대응 | LTE 가 끊겨도 차 안 녹화는 계속. 붙으면 5 초 안에 송출 재개, 브라우저는 자동 복구 |
| 보안 | 팀 계정으로 로그인한 사람만 시청. 송출은 차량 토큰 + SRT 암호가 있어야만 |

## 1. 차량 하드웨어

| 부품 | 추천 | 이유 · 주의 |
|---|---|---|
| 컴퓨터 | **라즈베리 파이 4 Model B** (2 GB 이상) | H.264 **하드웨어** 인코더가 있음. 파이 5 는 하드웨어 인코더가 없어 CPU 로 인코딩 → 밀폐 케이스에서 발열 |
| 카메라 | **카메라 모듈 3 Wide** (IMX708, 대각 120°, HDR) | 작고 가벼움. 자동 초점은 진동에 헤매므로 설정에서 **초점 고정** (2 m, 광각이라 약 1 m ~ 무한대 선명) |
| 카메라 (대안) | HQ 카메라 M12 + 광각 M12 렌즈 | 렌즈에 움직이는 부품이 없음. 모듈 3 에서 진동 번짐이 심하면 이쪽으로 |
| 카메라 (대안) | 글로벌 셔터 카메라 (IMX296) | 롤링 셔터 젤로 현상이 없음. 대신 1.6 MP (1456×1088) |
| 통신 | USB LTE 모뎀 또는 통신사 LTE 라우터 (USB 테더링) + 데이터 쉐어링 USIM | 국내 통신사에서 개통되는 기기인지 먼저 확인. 외부 안테나 (MIMO 2 개) 를 롤케이지 가장 높은 곳에 |
| 전원 | 차량용 DC-DC 12 V → 5 V **5 A** (입력 9 ~ 36 V) + 퓨즈 3 A | 파이 4 는 5.1 V 3 A, LTE 모뎀이 순간 2 A. 시동 · 크랭킹 때 전압이 떨어져도 버티는 넓은 입력 범위 |
| 저장 | 고내구성 (High Endurance) microSD 64 GB 이상 | 4 Mbps 기준 64 GB ≈ 35 시간 |
| 케이스 | 알루미늄 방수 케이스 (IP65 이상) | 케이스가 방열판 역할 (파이 · 모뎀에 써멀 패드). 렌즈 창에 발수 코팅 |
| 방진 | 고무 · 실리콘 댐퍼 4 점 | 아래 '장착' 참고 |
| (선택) GPS · IMU | u-blox GPS, 6 축 IMU | 시각 동기 · 트랙 지도 · 속도 오버레이, Gyroflow 후보정 |

부품 합계는 대략 30 ~ 45 만 원 선 (USIM 요금 · 중계 서버 비용 별도, 구매 시점 시세 확인).

## 2. 장착 — T-cam 위치

- **위치**: 리어 롤 후프 위쪽 가로 부재 **아래쪽**, 운전자 헬멧 뒤 · 위에서 앞을 보게. 헬멧 · 스티어링 · 앞 차체 · 트랙이 한 화면에 들어오는 F1 T-cam 구도.
- **롤케이지 바깥으로 튀어나오지 않게**: Baja 는 전복이 잦아 케이지 위에 얹으면 그대로 부서지고, 규정 위반이 될 수 있음. 헬멧 여유 공간 (클리어런스) 영역 안에도 두지 말 것. 카메라 마운트는 기술검차에서 승인받는 항목이므로 **대회 규정집의 카메라 · 전장 조항을 먼저 확인**.
- **일체형 포드 추천**: 카메라 + 파이 + LTE 모뎀을 한 케이스에. CSI 케이블이 짧아져 (진동 · 노이즈에 약함) 고장이 줄고, LTE 안테나가 가장 높은 곳에 온다. 아래로는 전원선 하나만.
- **진동**: 단기통 엔진은 회전수 / 60 Hz (1 차), 그 절반 (폭발) 의 진동을 낸다. 예: 3,600 rpm 이면 60 Hz · 30 Hz. 댐퍼를 단 마운트의 고유 진동수를 이보다 충분히 낮게 (10 ~ 15 Hz) 잡으면 진동이 걸러진다. 너무 무르면 범프에서 출렁이므로 시험 주행 영상으로 맞춘다. 마운트 자체 (브래킷) 는 짧고 단단하게.
- **화면 젤로 · 번짐**: 설정에서 셔터를 짧게 (`rpiCameraExposure: short`), 초점 고정. 그래도 심하면 글로벌 셔터 카메라.
- **진흙 · 물**: 렌즈 창 발수 코팅 + 짧은 후드. 물웅덩이 구간 뒤 화면이 흐려지는 건 감수.
- **열**: 한여름 직사광선 아래 밀폐 케이스는 파이가 스로틀링할 수 있음. 밝은 색 · 차광, `sem-cam-health` 로 온도와 throttled 확인.

## 3. 전원 · 배선

```
배터리 12 V ─ 퓨즈 3 A ─ (규정이 요구하면 마스터 스위치 뒤) ─ DC-DC 12→5 V 5 A ─ 파이 4 (USB-C) ─ USB ─ LTE 모뎀
```

- 킬 스위치 · 사고로 전원이 끊겨도 녹화는 **1 초 조각 (fMP4)** 으로 쓰고 있어 마지막 1 초만 잃는다.
- SD 카드 손상까지 막으려면 루트 파일 시스템을 오버레이 (읽기 전용) 로 두고 녹화만 별도 저장소 (USB SSD 등) 에. 더 필요하면 슈퍼커패시터 UPS 로 10 ~ 20 초 버티며 정상 종료.
- 접지 · 전선은 엔진 · CVT 에서 떨어뜨리고 케이블 타이로 진동에 쓸리지 않게.

## 4. 통신 (차량 → 중계)

- **LTE 상향 속도가 핵심**. 대회장에서 미리 속도를 재서 화질을 정한다 (상향 10 Mbps 이상이면 1080p 4 Mbps, 붐비면 720p 2 Mbps). 관중이 많은 날엔 떨어진다.
- **SRT**: 잃어버린 패킷을 재전송으로 메우는 방송용 프로토콜. 재전송 여유 (`SRT_LATENCY_MS`) 800 ms 가 기본 — 화면이 자주 깨지면 늘리고, 지연을 줄이려면 줄인다. AES 암호화 (SRT 암호) 로 LTE 구간도 암호화.
- 차량은 통신사 NAT 뒤에 있어 브라우저가 직접 붙을 수 없다 → 공인 주소가 있는 **중계 서버** 가 필요.

## 5. 중계 서버 (클라우드 VM)

- 서울 리전 소형 VM 1 대 (1 vCPU · 1 GB 로 충분: 영상을 다시 인코딩하지 않고 복사만 함). 시청자 20 명 × 4 Mbps = 나가는 트래픽 80 Mbps, 2 시간이면 약 72 GB 이므로 **VM 의 전송량 한도** 를 확인.
- 도메인 하나 (예: `cam.<팀 도메인>`). Cloudflare DNS 를 쓰면 **프록시 끄기 (회색 구름)** — WebRTC 의 UDP 는 프록시를 지나지 못한다.
- 열 포트: TCP 80 · 443 (HTTPS), UDP 8890 (SRT 수신), UDP · TCP 8189 (WebRTC 미디어. TCP 는 UDP 가 막힌 학교 · 회사 망용).
- 중계 서버도 받은 영상을 14 일 동안 녹화 (차량이 크게 부서져도 영상이 남도록).

## 6. 팀 웹 (SEM Workbench) 연결

1. **Worker** (`sem-ai`): `worker/cam.js` 를 붙인다 (파일 머리 주석에 붙이는 법). 엔드포인트 두 개:
   - `GET /api/cam/jwks.json` — 중계 서버가 토큰을 검사할 공개 키
   - `POST /api/cam/token` — 기존 세션 확인을 통과한 팀원에게 30 분짜리 시청 토큰 + WHEP 주소
2. **앱**: 라이브 탭에 `web/mediamtx-reader.js` 와 `web/live-cam.js` 를 넣고
   ```js
   const cam = SemLiveCam.mount(document.getElementById('live'));  // __SEM_AUTH__ 의 api · token 을 씀
   // 탭을 떠날 때 cam.destroy();
   ```
   플레이어는 토큰이 끝나기 2 분 전에 새 토큰으로 두 번째 연결을 열고, 첫 화면이 나오면 바꿔 끼운다 (화면 안 끊김). 차량 신호가 없으면 '차량 신호 없음', 돌아오면 자동 재생. 해상도 · fps · 비트레이트 · 손실률을 화면에 표시.
3. **개인정보 처리방침**: 영상에 운전자 등 사람이 찍히고 중계 VM 회사에 녹화가 저장되므로, 처리방침의 '처리 위탁 · 국외 이전' 표에 중계 서버 제공사와 '라이브 영상 · 녹화' 항목을 더하는 것을 검토.

> 이 저장소 (`sem-chassis-site`) 는 배포본만 올라가는 곳이라 (main 이 배포 때마다 새로 써짐) 앱 · Worker 소스가 없습니다. 이 폴더는 앱 소스 저장소로 옮겨서 위 1 · 2 를 붙이면 됩니다.

## 7. 설치 순서

```bash
# (1) 키 만들기 — 개인 키 파일은 저장소에 올리지 말 것
node worker/cam-keys.mjs new > cam-private.jwk.json
npx wrangler secret put CAM_JWT_PRIVATE_JWK < cam-private.jwk.json      # Worker 에 개인 키
#     Worker 변수: CAM_WHEP_URL=https://cam.<도메인>/cam/whep  → 배포
node worker/cam-keys.mjs publish-token --key cam-private.jwk.json --days 365   # 차량 송출 토큰
openssl rand -hex 20                                                    # SRT 암호 (차량 · 중계 같은 값)

# (2) 중계 서버 (Docker 설치된 VM)
cd relay && cp secrets.env.example secrets.env && nano secrets.env && ./setup.sh

# (3) 차량 (라즈베리 파이 OS 64-bit, 카메라 연결 뒤)
cd car && cp secrets.env.example secrets.env && nano secrets.env && sudo ./setup.sh
sem-cam-health                                                          # 카메라 · 송출 · 온도 · 저장 공간
#     카메라 각도 맞추기: 같은 Wi-Fi 노트북에서 http://<파이 IP>:8889/cam
```

**송출 토큰 만료일 주의**: MediaMTX 는 토큰의 만료 시각이 되면 연결을 끊는다. 대회 기간이 넉넉히 들어가게 발급하고 (`--days`), 키를 바꾸면 송출 토큰도 다시 발급한다.

## 9. 시험 (이 폴더에서 한 일)

`test/e2e.mjs` 가 실제 설정 파일 · Worker 모듈 · 웹 플레이어를 그대로 써서 한 PC 안에서 끝까지 돌려 본다 (카메라만 ffmpeg 시험 화면으로 대신). MediaMTX v1.21.3 · 헤드리스 크로미움에서 모두 통과:

- 차량 → 중계 SRT 송출 (JWT · 암호), `sem-cam-health` 상태 읽기
- 막혀야 하는 것: 토큰 없음 · 틀린 세션 · 다른 경로 토큰 · 만료 토큰 · 다른 키로 서명한 토큰 · 시청 토큰으로 송출 · 틀린 SRT 암호 → 모두 거절, 공개 키에 개인 키 값 없음
- 브라우저 재생 시작 약 1 초, 1280×720 30 fps, 통계 표시
- 토큰 수명 60 초로 72 초 지켜봄 → 새 토큰으로 갈아 끼우는 동안 화면 끊김 없음
- 송출을 끊으면 '차량 신호 없음', 다시 보내면 약 2 초 만에 자동 복구
- 차량 · 중계 양쪽 녹화 파일 (fMP4) 생성 · 재생 확인

```bash
MEDIAMTX=/path/to/mediamtx node test/e2e.mjs      # 필요: mediamtx v1.21.x, ffmpeg (libx264 · srt), playwright
```

실험실 안 (같은 PC) 시험이라 **LTE 의 손실 · 지연 · 실제 카메라 · 진동은 시험하지 못했다** — 차에 달고 트랙에서 확인할 몫.

## 10. 다음 단계 (선택)

- **텔레메트리 오버레이**: F1 중계 그래픽처럼 속도 (GPS) · 엔진 rpm · CVT 온도 · G 값을 영상 위에. 파이가 10 Hz 로 Worker (Durable Object WebSocket) 에 보내고 플레이어가 HTML 로 겹쳐 그림.
- **Gyroflow 후보정**: IMU 를 같이 기록해 녹화 영상을 흔들림 없이.
- **녹화 고화질 · 라이브 저화질 분리**: MediaMTX `rpiCameraSecondary` 로 두 번째 스트림. 파이 4 CPU 여유를 먼저 확인.
- **통신사 두 곳 동시 사용** (본딩) 으로 끊김 줄이기.

**시간이 없을 때의 대안**: RTMP 라이브를 지원하는 액션캠 + 휴대폰 핫스팟 → 중계 서버 RTMP 수신 (relay 설정에서 `rtmp: true`, 송출 토큰은 `?token=`) → 같은 웹 플레이어. 장비는 간단하지만 지연이 몇 초로 늘고, 발열 · 배터리 · 진동 마운트가 약점.
